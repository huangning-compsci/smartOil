# 真实设备并发采集与实时监控设计

## 目标

将数据采集与监控模块中的两套虚拟设备并发压测替换为面向当前真实设备的统一开关。开关开启后，系统持续并发采集最新数据、立即执行报警检测，并在触发报警时即时输出报警信息；关闭开关或退出程序时，所有采集和报警处理线程必须安全结束。

## 功能边界

- 删除原菜单 4 的千台虚拟设备串行/并行性能对比。
- 删除原菜单 7 的千台虚拟设备后台压测。
- 删除仅供上述压测使用的测试设备工厂和监控引擎压测模式。
- 保留单设备采集、批量采集、实时状态台账和设备启停功能。
- 统一开关只管理开启时 `FrDev.allDevices()` 返回的设备快照；设备增删后需关闭再开启，以刷新监控设备清单。

## 交互设计

数据采集与监控菜单的第 4 项根据当前状态显示为“开启并发采集与实时监控”或“关闭并发采集与实时监控”。

开启时：

1. 获取当前真实设备清单。
2. 清单为空时拒绝启动并提示用户。
3. 创建一个新的 `MonitorEngine` 并启动持续采集。
4. 已开启时不得再次创建或启动第二个引擎。

关闭时：

1. 停止提交新的采集轮次。
2. 等待正在执行的采集任务结束。
3. 处理完已经进入报警队列的事件。
4. 结束报警消费者线程并清除当前引擎引用，使开关可以再次开启。

用户退出整个系统时，如果开关仍处于开启状态，系统自动执行相同的关闭流程。

## 并发采集与报警数据流

`MonitorEngine` 为每台设备安排周期性任务，`DataCollectionTask` 每次只负责一轮处理：

1. 非投运设备或不支持采集的设备跳过本轮。
2. 投运设备调用自己的 `collectData()` 更新最新采集值。
3. 同一任务立即对这份最新值调用 `checkAlarm()`。
4. 未触发报警时结束本轮；触发报警时把不可变的 `AlarmException` 事件放入阻塞队列。
5. 单独的报警消费者按队列顺序处理事件，避免采集线程同时修改正式报警记录和运维任务队列。

每条报警在被消费者处理时立即打印，至少包含报警时间、设备编号和报警描述；随后写入 `AlarmLog` 并调用 `FrMnt.addTask()` 创建运维任务。单台设备的采集或检测失败只记录本轮错误，不取消该设备之后的周期任务，也不影响其他设备。

## 代码改动范围

- `FrUi.java`：持有程序生命周期内唯一的监控引擎；替换菜单和开关逻辑；删除两套虚拟压测；退出时自动关闭。
- `MonitorEngine.java`：移除压测模式，提供运行状态查询，处理并即时打印正式报警，保持可靠停止语义。
- `DataCollectionTask.java`：保留“采集最新数据后立即检测报警”的单轮职责，仅在测试暴露的问题要求时做最小调整。
- `devices/FluidTransportDevices/CentrifugalPump.java`：删除仅供虚拟压测使用的 `createTestDevice()`。
- `README.md`：把模拟并发描述更新为真实设备并发采集与实时报警监控。

不修改设备编号、设备存储、报警判断阈值、报警确认流程和运维任务处理规则。

## 验证标准

实现遵循测试先行。临时测试程序放在项目目录外，不作为项目文件提交。

1. 开关对当前真实设备启动并发采集，未投运设备被跳过。
2. 最新采集值触发报警后，即时输出时间、设备编号和描述，并写入报警记录及运维任务。
3. 无报警的数据不产生报警输出、报警记录或运维任务。
4. 重复开启不会创建第二组线程。
5. 关闭时完成在途任务和队列排空，关闭后不存在采集线程或报警消费者线程。
6. 关闭后可以重新开启并读取新的设备快照。
7. 退出系统时自动关闭仍在运行的监控引擎。
8. 全部 Java 源码编译通过，并用控制台真实操作验证开启、即时报警、关闭和退出流程。
